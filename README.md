# Kero

Kero is an educational **simulator** of a small computer, built step by step in Rust. The name comes from the Japanese "kero kero," a frog's croak. A frog is the project's mascot and a possible starting point for its visual style; the machine design stays independent of the mascot.

This is a fresh start: no Python implementation or completed exercises are carried over. The learner builds the virtual computer one capability at a time.

## Start

1. Copy the **contents** of this starter pack into the root of a new project. Keep the directory structure shown below.
2. Install the stable Rust toolchain with [`rustup`](https://rustup.rs/) if needed. Check `cargo --version`, `cargo fmt --version`, and `cargo clippy --version`. The package uses Rust edition 2024; update an older toolchain before building. No third-party crate is needed for the first milestones.
3. From the new project root, run `cargo run`. The message confirms only that the starter builds; it does not mean the virtual computer exists yet.
4. Read [the learning guide](docs/learning-guide.md), [architecture](docs/architecture.md), [roadmap](docs/roadmap.md), and [progress](docs/progress.md). Begin with task 1.1.

## Routine checks

```sh
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
cargo run
```

`cargo check` gives quick compiler feedback while working. Run the full checks when a capability is ready for review. `Cargo.lock` is generated by Cargo on first build; keep it with this application when using version control.

## Layout

```text
Cargo.toml              Package configuration
src/main.rs             Temporary runnable entry point
src/                    Learner-owned simulator modules, added as tasks arrive
docs/architecture.md    Machine boundaries and chosen design
docs/roadmap.md         Capability sequence
docs/learning-guide.md  Learning rhythm and help levels
docs/progress.md        Fresh-start journal
AGENTS.md               Rules for Codex in the new repository
```

The Rust standard library is enough for the CPU, assembler, language, virtual disk, and runtime. An optional window crate is considered only when the independently testable framebuffer is working. See [display and memory notes](docs/rust-design-notes.md).
